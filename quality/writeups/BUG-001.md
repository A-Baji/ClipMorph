# BUG-001 - Empty upload selection skips all shared-workflow uploads

> Generated by Quality Playbook v1.5.6 — Andrew Stellman
> Date: 2026-09-24 · Project: short-form-content-converter

## Summary

The CLI treats an empty `upload_to` list as all supported platforms, but the shared workflow treats it as no platforms. A dashboard job can therefore finish without uploading anything.

## Spec reference

`clipmorph/cli.py:147-151` defines the generated `upload_to` value as an empty list for all platforms; `docs/CLI_WEB_PARITY.md` requires CLI and API to use the same workflow contract.

## The code

`workflow.py:15-18` reads the configured list and immediately lowercases it. It does not normalize an empty list to the supported platform set, unlike `__main__.py:16-29`.

## Observable consequence

With `upload_to: []`, `UploadPipeline` receives no enabled platform flags and returns an empty result map. The job can be marked completed without any platform upload.

## The fix

```diff
--- a/clipmorph/workflow.py
+++ b/clipmorph/workflow.py
@@ -16,6 +16,8 @@ def execute_job(manifest: JobManifest, token: CancellationToken,
     no_upload = bool(configuration.get("no_upload", False))
     enabled_platforms = configuration.get(
         "upload_to", ["youtube", "instagram", "tiktok", "twitter"])
+    if not enabled_platforms:
+        enabled_platforms = ["youtube", "instagram", "tiktok", "twitter"]
     enabled_platforms = [platform.lower() for platform in enabled_platforms]
```

## The test

`quality/test_regression.py::RegressionTests.test_bug_001_empty_upload_list_means_all_platforms` asserts the four platform flags. The unpatched red phase fails; the disposable green phase passes after applying the fix patch.
