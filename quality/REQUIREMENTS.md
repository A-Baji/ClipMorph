# Requirements

> Generated by Quality Playbook v1.5.6 — Andrew Stellman
> Date: 2026-09-24 · Project: short-form-content-converter

ClipMorph converts media and publishes platform-specific short-form content. Actors are creators, operators, local CLI users, dashboard users, and external platform clients. Highest-risk areas are resumable state, cancellation, duplicated CLI/web orchestration, concurrent uploads, and policy enforcement.

## REQ-001 - Cancellation state

Tier: 3. Functional section: Job lifecycle. Use case: UC-01. Source: `workflow.py:47-49`, `service.py` cancellation flow.

When cancellation is observed, the job must persist a terminal `cancelled` state or an explicitly documented resumable state, and must not remain indefinitely active. Test preflight, conversion, and upload cancellation points.

## REQ-002 - CLI and web parity

Tier: 3. Functional section: Execution parity. Use case: UC-02. Source: `__main__.py:139-143`, `workflow.py:28-82`, `docs/CLI_WEB_PARITY.md`.

Equivalent CLI and web jobs must apply the same preflight rules, capability policy, artifact metadata, configuration, and terminal status.

## REQ-003 - Configuration precedence

Tier: 3. Functional section: Configuration. Use case: UC-03. Source: `cli.py:106-121` and README configuration precedence.

Explicit CLI values must override config-file values, and config-file values must override parser defaults. Boolean false, empty lists, and platform overrides are valid explicit values.

## REQ-004 - Platform result preservation

Tier: 3. Functional section: Upload lifecycle. Use case: UC-04. Source: `upload_pipeline/__init__.py:48-84,228-260`, `job.py:127-136`.

Each requested platform must retain its own success or failure result. Concurrent completion and retry order must not erase prior platform state or mark incomplete work as fully published.

## REQ-005 - Policy transformation enforcement

Tier: 3. Functional section: Upload policy. Use case: UC-04. Source: `policy.py:87-114` and platform mapping in `upload_pipeline/__init__.py`.

When policy transforms content, the uploader must consume the transformed value; a decision that reports truncation must not be paired with an upload of the original over-limit value.

## REQ-006 - Source-verified resume

Tier: 3. Functional section: Resumability. Use case: UC-05. Source: `job.py:73-90`, `__main__.py:105-112`.

Resume must reject a missing, changed, or mismatched source path/content and preserve the existing artifact and per-platform state for a matching source.
